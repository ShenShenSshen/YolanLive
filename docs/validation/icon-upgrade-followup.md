# 覆盖升级图标残留跟进

2026-11-03，版本 1.1.5。本次仅诊断和隔离升级验证，未修改安装器、版本或公开软件包，未发布 GitHub。

## 用户现象及已确认事实

- 用户报告安装 1.1.5 后，桌面仍显示旧图标。原安装目录中的版本化 ICO、快捷方式目标与图标路径均已更新，图标文件 SHA-256 与当前 D4 源文件相同。
- 对原桌面入口发送定点更新通知、备份后重建同名快捷方式，用户均确认显示仍未改变。不能将这两次操作记为修复成功。
- Shell API 提取的 16、32、48 和 256 像素图标显示 D4，但这不等于 Explorer 已显示相同图像。快捷方式箭头叠加也会使其像素与直接提取 ICO 不同，不能以两者哈希不等判定旧图残留。
- 用户随后卸载并重新安装，确认图标正确。重装后日常安装目录也发生变化；卸载、重建安装与路径变化没有分别验证，因此不能仅据此认定某一缓存为根因。

## 本次隔离升级复现

使用已有 `YolanLive-1.1.4-x64-Setup-test.exe` 和 `YolanLive-1.1.5-x64-Setup-test.exe`，不重新构建、不覆盖正式发布包。临时目录与缓存位于 D 盘，使用独立测试 AppId、`游岚-test` 桌面／开始菜单入口和假设置文件；未运行测试安装中的播放器或读取日常账号。

1. 测试版 1.1.4 安装到隔离目录，读取并提取桌面快捷方式的旧图标，使 Shell 实际加载旧资源。
2. 不卸载，覆盖安装测试版 1.1.5。安装版本、快捷方式目标、版本化图标路径均正确，假设置文件哈希保持不变。
3. Shell 提取结果由旧版深色图标变为 D4 风翼；系统图像索引由 256 变为 257。用户观察临时桌面入口，也确认显示“浅蓝底、蓝青风翼新图标”。
4. 卸载测试身份，独立核对测试注册表、两处快捷方式、测试 exe 与假资料全部移除。按日常注册表当前位置核对，原软件仍为 1.1.5，开始菜单入口指向日常安装及版本化图标。检查时用户桌面与公共桌面均没有日常“游岚”入口，未主动新建；隔离安装日志中的桌面目标仅为 `游岚-test.lnk`。

本机原始诊断脚本、安装日志和 Shell 图标样本保存在忽略提交的 `artifacts/icon-diagnosis/`。日志可能包含本机路径，不作为公开发布资产。

## 结论与边界

本次隔离的真实旧版到新版覆盖升级未复现残留，且同时经过 Shell 读取与用户桌面观察。当前用户安装已由卸载重装恢复正常；原现象具体原因仍未确认，不能声明安装器已修复或 TDD 红绿验证通过。没有以“删除并重建快捷方式”等已在原问题上失败的操作代替根因修复。

若再次出现，应先保留问题现场，对同一入口记录 Explorer 实际显示、安装位置、快捷方式与图标资源，再开展单变量验证。自动化检查应区分图标文件、快捷方式元数据、Shell 提取结果和桌面最终显示四个边界。现有 `InstallerCheck.ps1` 主要验证前两个边界；不能据其通过宣称覆盖了 Explorer 缓存残留。

本轮未更改应用逻辑，无需重复完整播放或性能测试；既有全屏视口失败与平台网络限制仍按原发布记录保留。
