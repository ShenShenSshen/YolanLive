# 关注页按开播状态分组 · 本地预览

2026-11-02。基于已发布 v1.1.3，版本号保持不变；本次仅交付源码和完整预览目录，不生成安装包、不发布 GitHub、不修改日常安装或资料。

## 展示与数据

- 同一关注页依次展示“直播中”“未开播”“状态待确认”，标题附数量，所有非空分组始终展开；空分组由原生 GroupStyle 隐藏。
- 保留头像、姓名、平台和现有卡片高度；使用现有圆体分组标题、微软雅黑 UI 正文、主题字号。未开播用较深灰蓝文字与浅灰蓝状态底色，不降低整个卡片或主播姓名的透明度；未知状态用独立标识。
- 页面首次进入先显示所有已保存关注，再确认状态；刷新保留原内容，成功后重新分组。查询失败、超时或平台不可用进入“状态待确认”，不伪装成未开播。
- 搜索、打开房间、右键移除、管理、导入导出继续保留；管理入口文案缩为“管理关注”。不可用平台的旧记录仍可见，打开时给出提示而不访问空对象。
- 运行时使用可空状态区分三种情况，保留原 LiveStatus 布尔访问兼容；不修改 SQLite 表结构、JSON 资料格式或平台接口。
- 使用一个原生分组 GridView 与 ItemsWrapGrid，保留虚拟化和原有自适应卡片尺寸，不使用多个列表套外层 ScrollViewer，不新增轮询或动画计时器。
- 继续最多 4 个关注状态查询并行、单项 10 秒期限与页面取消，迟到结果不得覆盖已离开的页面；不额外请求房间详情或视频流。

## 验证

使用 D 盘缓存构建并运行 `tests/FavoriteGroupCheck.ps1`，所有资料位于隔离访客目录，使用受控平台响应，不读取日常账号。结果见 `favorite-groups/checks.txt`：

1. 现有浏览、关注及画质偏好检查通过；旧“停播隐藏”断言按已确认的新行为改为同时显示并正确分组，未删除错误保留和数据完整性检查。
2. 首次进入同时保留开播、未开播、查询失败及不可用平台记录；未知状态不进入未开播组。
3. 浅色／深色、1280×720／640×360 原生页面加载、状态标签、卡片宽度及键盘焦点通过。
4. 刷新后状态迁移、分组数量更新，以及取消后迟到响应不改写内容通过。
5. 移除未开播关注同步更新分组、数量和数据库，通过。

补查旧平台记录时，最初夹具尝试直接保存一个未注册平台，被既有 AddFavorite 校验拒绝，导致测试找不到记录；原始结果保留在 `favorite-groups/checks-invalid-fixture.txt`。夹具改为“平台仍注册时关注，随后平台不可用”，继续通过同一保存／加载接口验证，未放宽断言或修改保存校验。

浅／深色未开播及未知标签的配色计算对比度分别为 6.34、5.23、7.67、7.97，均高于 4.5:1，见 `favorite-groups/contrast.json`。高对比度资源引用系统窗口色与系统文字色；未切换系统模式或重新验证 150%／200% 实机缩放。

本轮未运行四平台真实账号状态查询、完整播放器回归或长期性能对照；实际平台返回的状态仍依赖现有接口语义。没有更改更新下载或处理其既有实网超时问题。
